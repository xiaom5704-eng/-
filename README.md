# 智慧醫療助理（MedSafe AI）

藥物專案：以 React + Express + SQLite 建立的教學應用，提供藥品資料查詢、藥袋候選名稱辨識，以及依諮詢對象年齡調整的一般照護資訊，涵蓋嬰幼兒、兒童、青少年、成人與高齡者。

## 在 VS Code 啟動本機網頁

專案以本機網頁為主要使用方式，不需要 Windows 桌面安裝程式。首次取得專案時，在終端機執行：

```bash
git clone https://github.com/xiaom5704-eng/-.git medicine-app
cd medicine-app
npm ci
npm run data:install
npm run dev
```

也可從 GitHub 的 **Code → Download ZIP** 下載並解壓縮。已下載時，用 VS Code 開啟含有 `package.json` 的資料夾，在「終端機 → 新增終端機」從 `npm ci` 開始執行，略過 `git clone` 與 `cd`。請使用 Node.js 24。首次安裝套件及 OCR 模型需要網路。

`data:install` 僅供首次安裝：下載約 310 MB 的 2026-09-28 固定公開資料快照，核對 ZIP 與全部資料檔案後才建立 `data/`。包含本機清晰圖片、6,146 張可用藥錠參考及六份已核對的仿單副本。已經有 `data/` 時會拒絕覆蓋；資料備妥後，日常只需 `npm run dev`，開啟終端機顯示的網址（預設 `http://localhost:3000`）。這不是資料自動更新指令。

若先啟動網頁再安裝資料也能恢復：找不到藥品資料庫時，服務使用暫存空資料，不建立阻擋安裝的 `data/drugs.db`；「藥物辨識」會顯示「準備本機資料」及安裝步驟。安裝後須停止並重啟服務，再重新整理網頁。對話仍正常保存；既有資料庫不會改為暫存或被覆蓋，損毀的資料庫會明確啟動失敗。

已下載資料 ZIP 時可用 `npm run data:install -- --file="資料包 ZIP 路徑"` 離線安裝。自訂資料庫／圖庫路徑的使用者請沿用既有匯入流程。詳細步驟見[完整資料包與首次啟動](docs/GitHub下載與啟動.md)。只需基本藥名與交互作用資料時，也可自行執行 `npm run data:sync`。本機查藥、OCR、圖片候選比對及年齡案例不需要 Gemini 金鑰；自由問答仍需 Gemini 或已啟動的 Ollama。

## 依年齡諮詢

聊天、症狀回答與自動標題**只使用畫面選定的引擎**。窄螢幕也能切換 Ollama／Gemini；設定金鑰不會讓 Ollama 失敗時自動改送 Gemini。失敗後可修復連線或手動切換，再按「重試回答上一個問題」，沿用原問題與原年齡。症狀頁保留表單，可再次取得建議。

展開「連線狀態與使用方式」可查看 Ollama 設定模型、重新檢查，並區分服務連不上、模型未安裝或回應格式錯誤。若服務已啟動但缺少設定模型，會列出已安裝名稱，方便在 VS Code 調整 `.env` 的 `OLLAMA_MODEL` 後重新啟動。這是連線／模型清單檢查，不能保證模型推論成功；依 [Ollama 的模型清單 API](https://docs.ollama.com/api/tags) 取得資料。

對話與症狀頁可填寫年齡（歲／月／天），也可在問題中直接說明。填寫的年齡會隨問題傳給所選 AI 並儲存至本次對話；未填時參考本次問題及對話上下文，不預設為嬰兒。新建或切換對話會清空年齡與症狀草稿，已送出的年齡仍保留在原對話紀錄中。請為不同對象建立不同對話。

年齡客製化目前用於 AI 一般照護資訊與追問內容，並非個人化診斷或劑量計算。藥品交互作用仍是成分層級查詢；仿單保留來源提供的兒童、高齡者及特定族群段落，不由 AI 補寫年齡限制。

首次聊天會將對話與第一個問題一起保存；寫入失敗不留下空對話，未確認保存前保留目前草稿。同一頁面重試相同問題與年齡時沿用請求識別，避免伺服器已寫入但回覆中斷造成重複；等待期間另外輸入的下一段草稿也會保留。這份未確認的問題草稿只留在目前畫面，重新整理或關閉分頁不保證保留。問題保存後須成功載入最新歷史才會呼叫 AI；讀取失敗可先「重試載入」，再續答原問題。

聊天或症狀回答已生成但無法確認儲存時，畫面會保留原回答並提供「重試儲存回答」，側欄標示待存的對話。重試不重新呼叫 AI，也不改用新輸入的年齡或問題；成功後清除暫存。同一請求重送不新增重複訊息，症狀問答以同一交易保存。待存內容使用該瀏覽器分頁的 `sessionStorage`，不含金鑰；同分頁重新整理可恢復，但關閉分頁不保證保留。若暫存被禁用或空間不足，會明示僅保留於目前畫面，須先完成儲存。

模型連線失敗或停止等待後，最後一個未回答的聊天問題會顯示「重試回答上一個問題」。重試先重新讀取歷史，沿用原問題與原年齡；即使年齡欄已修改，也不把新的年齡套入舊問題。舊版沒有請求識別的歷史問題也可續答，不新增重複問題。症狀頁停止後保留表單，可再按「獲取建議」。

藥物報告保存失敗時也會保留原報告，提供「重試儲存報告」與側欄提示；新對話尚未建立亦可從分頁暫存找回。重試保留原年齡、查詢時間、來源及摘要，不再次查藥或呼叫 AI。同一份報告重送不新增重複訊息；首次保存會將對話與報告放在同一交易，失敗不留下空對話。待存報告完成後，才可另外保存修改年齡或摘要後的新報告。切換對話時，已開始的存檔仍寫入原對話，不會改存至新對象；使用者刪除對話後，延遲請求也不能重新建立它。

等待回答時可按「停止等待」；切換對話也會中止原請求，避免晚到的結果寫入或自動切換另一個模型。Ollama 代理會關閉送往模型的請求；Gemini 使用 SDK 的用戶端取消，不能保證雲端運算或用量計費停止。回答已進入儲存階段時不提供中斷寫入，保存失敗仍沿用上述恢復機制。

回答旁的喇叭按鈕會朗讀已排版的文字，長文分段播放，再按一次即可停止。修改症狀或年齡使舊建議消失、切換頁面或對話時，也會停止原本的朗讀；歷史回答本身不會被改寫。語音輸入與播放使用瀏覽器的語音服務，支援情況、發音與是否需要連線依瀏覽器及裝置而定。

藥物辨識頁另有「一鍵載入 1 個月案例」，以本機資料載入 5 款示範藥物，搭配有限品項的來源規則顯示年齡及併用提醒，可切換 4／30／70 歲比較，不呼叫 Gemini 或 Ollama。這不是完整處方審核；DDInter 資料不足仍保留，不把藥理推論冒充資料庫配對。操作、藥品選擇假設、來源版本與圖片庫缺口見 [比賽案例展示指南](docs/比賽案例展示指南.md)。

## 藥物查詢流程

臺灣仿單與外盒另有本機索引，隨首次資料安裝提供；目前快照 29,875 個品項。已確認藥品會依許可證及完整品名尋找官方入口，顯示於「藥品說明書」。索引查找離線完成，開啟原文件仍需網路；不等同已保存 PDF。既有資料庫可執行 `npm run data:import-labels` 離線補入，更新官方索引用 `npm run data:import-labels -- --download`。詳見[索引範圍與維護](docs/本機仿單索引.md)。

1. 藥錠照片預設以本機 DINOv2 模型比對 TFDA 參考圖，可上傳同一種藥的正反面、裁切並補充刻字。藥盒可切換「藥盒照片比對」，搜尋獨立的本機包裝圖庫。藥袋、PDF 及包裝文字可用本機 OCR；也可手動輸入，或明確選用 Gemini 輔助。
2. 圖片比對列出最多 8 個候選及可放大的本機參考圖，不自動確認藥品。本機 OCR 結果可校正，點選一行藥名或刻字查本機 TFDA 資料；Gemini 輔助則批次比對。失敗不自動改查外部 API 或上傳雲端。一般搜尋、外觀比對與報告也優先顯示已下載的本機參考圖，尚未收錄的圖會標示需要連線。
3. 核對後按「確認並分析」，直接使用本機成分、DDInter 與先前保存的仿單。需要時再按「補查線上仿單與標準名稱」呼叫 RxNorm、openFDA；查得的仿單保留取得日期、來源與版本，之後可離線查看。線上 RxNorm 品項仍可選用。
4. 閱讀來源、查詢時間、資料涵蓋範圍與完整原文；可產生保留查詢狀態的多語摘要。
5. 將含來源的報告儲存至對話紀錄，再繼續討論。

手動查詢不需要 AI 金鑰。查無交互作用紀錄不代表安全；美國仿單不等於所選臺灣產品的仿單。本版不做任何年齡的個人劑量換算或處方建議。

部分成分在 TFDA 與 DDInter 使用不同寫法。專案保留有來源的精確對照，現在也能離線核對 `NIACINAMIDE (NICOTINAMIDE)`、`CYANOCOBALAMIN (VIT B12)` 與 `NIACIN (NICOTINIC ACID)`；不任意刪除括號、鹽類或濃度。核對依據與涵蓋範圍見[本機成分對照](docs/本機成分對照.md)。

另已核對 79 種括號內為鹽類／水合物的完整寫法，例如 `GENTAMICIN (AS SULFATE)`、`AMOXICILLIN (TRIHYDRATE)`。它們的精確 RxNorm 關係隨程式提供，可直接接回本機既有交互作用資料，保留原名、完整形式及取得日期；不需要重新下載資料或提供 API Key。未核對的括號寫法不會自動套用。

另隨附 2026-09-27 核對的 44 份 DDInter 成分頁快照，補上部分本機未收錄成分。首次 `npm run data:install` 自動補入；已有資料者可執行 `npm run data:apply-reviewed`，先備份再離線補入，不替換既有快照。來源、授權及固定版本見[補充資料說明](resources/ddinter/README.md)，不代表所有成分均已對照。

「拍照」會先顯示相機預覽，取得可用畫面後才能拍攝；權限拒絕、找不到相機或連線中斷時可重試，或取消後上傳檔案。取消、按 Escape 或離開藥物頁會停止相機，較早的授權結果不會覆蓋新畫面。拍下的照片先加入本次附件，可裁切並沿用 CV／OCR 流程；不會因拍攝就自動確認藥品。

本機搜尋支援完整許可證、全半形、品牌標點與分開的關鍵字，例如 `KBT`、`普拿疼 加強`。藥名與手動外觀候選每頁 20 筆，可翻頁查看全部符合結果，已確認品項不會因翻頁消失。`npm run data:check-search` 可驗證實際匯入資料的查找與分頁，產生紀錄於 `data/reports/`。

手動外觀查詢的形狀與顏色選項直接來自已匯入資料，包含來源列出的液劑、粉劑與顆粒劑。顏色可點選複選，例如來源用字「粉」，或「紅＋白」；再次點選可取消，也可手動輸入。多色須同時符合，完整刻字條件仍保留。更新外觀 CSV 後按「重新讀取資料狀態」即可更新選項；外觀篩選不代表照片已辨識成功。

單一中英文品名查不到時，可按「查詢相近品名」，查看本機來源中相差一個字的寫法，例如 `noscaplne` 可找到 `NOSCAPINE`。原輸入不自動改寫；核對後點選建議才重新搜尋，劑型篩選保持。此功能也適用 OCR 藥名查詢，僅提供字近的關鍵字，不代表照片已辨識成功；含數字／規格、許可證或藥錠刻字不套用拼字建議。詳細範圍見[搜尋規則](docs/drug-data.md)。

可選填劑型，候選與翻頁都依 TFDA 主檔原始細分類篩選，例如「錠劑」「膜衣錠」「內服液劑」各自查詢，不自動合併。掃描結果的藥名、規格與劑型可展開校正後再查；未知劑型會明示沒有對照，可清空後擴大查詢。未記載劑型的外觀紀錄不能視為符合指定劑型。這是來源欄位搜尋，不判定用藥適用性。

藥袋 OCR 同一行若夾帶「藥名：」「用法：」「數量：」等明確欄位，可展開「建議查詢」核對藥名與規格，再按「用核對後藥名查詢」。原文與分出的欄位文字保留，不把服用數量當成產品含量，不自動改字或確認藥品。沒有明確欄位、多筆藥名混在一行時仍須手動校正；藥錠刻字不套用這項整理。

也可輸入 `普拿疼500mg`、`warfarin 1 mg`、`希普利敏0.4mg/mL`。數字與單位會一起比對來源品名中的規格，不拿許可證數字或廠商文字代替；規格寫法、空格與小數點依[搜尋規則](docs/drug-data.md)處理。這是品名文字篩選，未將複方各數值對應至特定成分，也不換算劑量；品名未記載規格時，可移除規格改查藥名並核對仿單。掃描結果的獨立規格欄位也套用相同條件。

已查證的 RxNorm 成分標準名稱保留在本機，附來源、版本及核對日期，重啟或離線仍可重用。管理者可執行 `npm run data:enrich -- --limit=100` 分批補查；精確對照失敗會保留資料缺口。操作與限制見[本機成分對照](docs/本機成分對照.md)。

同一成分在 DDInter 使用不同名稱時，可透過兩個名稱各自的精確 RxNorm IN 紀錄連結。管理者執行 `npm run data:enrich-ddinter -- --limit=100` 補齊本機名稱紀錄；有多個 DDInter ID、只有鹽類／產品概念或缺少證據時不自動選定。藥品明細與保存報告會列出名稱核對來源。TFDA 的 `EQ TO` 別名也支援空格與連續標記，原文仍保留。

公開 CSV 未涵蓋的官方網站成分，可先核對 ID，再用 `npm run data:enrich-ddinter-web -- --id=DDInter1996` 保存配對快照。比賽案例已補回 Somin／Cypromin 的成分配對；本機查詢不連外。原始回應、來源、日期與雜湊分開保存，格式或跨來源衝突會停止匯入。重新安裝可用 `--file=封存檔.json` 離線還原；詳見[網站快照維護](docs/本機成分對照.md#補入公開-csv-沒有的官方網站配對)。

2026-09-24 另依本機未標示註銷品項的成分頻次，核對 35 份官方網站快照，補入 2,462 組原本缺少的配對；去重後總計 162,950 組。原始等級為 Unknown 的 504 組仍標示未知，沒有改成安全或特定危險等級；這批僅補配對等級，未補完整原因與處置。來源及驗證清單在 [DDInter 網站涵蓋報告](data/reports/ddinter-website-coverage-2026-09-24.json)。

已保存的官方快照若有機轉分類，結果會顯示「影響藥物代謝」「作用可能增強」等中文詞義，並保留原始分類、來源與取得日期。36 份快照共 14,160 組配對有分類，其中 4,544 組含 unknown，仍顯示「機轉尚不明」。分類不是完整原因或個人用藥建議；損毀、缺漏或來源分類衝突時不套用說明。[分類檢查與範圍](docs/本機成分對照.md#顯示官方機轉分類)。

若已核對的配對有官方詳細頁，可用 `npm run data:enrich-ddinter-details -- --id=270023` 保存交互作用、處置原文與來源文獻。此案例提供依來源整理的中文簡述，來源內容改變時不再套用舊簡述。一般查詢及查看原文皆讀本機，不需要 API Key；詳見[詳細說明維護](docs/本機成分對照.md#保存配對的詳細說明)。

「藥品說明書」可直接閱讀已存本機的臺灣 PDF 仿單，支援翻頁、放大，儲存報告後也能重開。目前目錄有六份已核對副本：五款案例品項（甜嗽錠、舒敏錠、希普利敏液、克瀉寧錠、芬康胃錠），以及普拿疼伏冒加強錠的 2021 歷史仿單。舒敏另有來源支持的 65 歲以上使用前諮詢提醒。`npm run data:cache-documents -- --all` 可取得已核對的版本，亦支援封存檔離線還原；不代表所有品項都有最新版仿單。公開資料快照仍含原先五份，新增的普拿疼副本可用 `npm run data:cache-documents -- --id=panadol-cold-extra-2021` 取得。來源及版本限制見[本機仿單說明](docs/本機仿單副本.md)。

仿單按完整成分集合篩選，可採已查證的 RxNorm 名稱關係，但不任意刪除鹽類字尾。最多分頁檢查 500 筆，找到 2 份不同 SPL Set 的相符資料便停止；尚未查完會明示，不能當作沒有資料。更新失敗保留舊紀錄及原日期，超過 7 天會提醒更新，並非醫療有效期限。美國資料不等於所選臺灣品項的仿單。

保存與顯示的文字段落包含注意事項、使用前詢問醫師或藥師、使用期間提醒、病人用藥資訊等 openFDA 欄位。舊紀錄若仍有同一查詢、同一仿單版本的原始快取，會在本機補齊並保留原日期；若無法核對，保留舊資料並提示補查。新紀錄另保留選中仿單的原始回應，供後續核對。已存入對話的歷史報告不改寫，請重新分析取得補齊後的報告。

含表格的段落可直接展開，保留合併儲存格、列群組、註記及上下標，也可左右捲動。保存至對話的報告同樣保留表格。已保存完整原始回應的舊仿單會自動補上表格，不需再呼叫 API；來源取得日期不變。來源 HTML 經 parse5 純解析後，以允許的靜態元素重建，不執行腳本、不載入來源圖片或外部樣式。若含尚不支援的圖片公式、錯誤跨欄格式或過於複雜的結構，會提示核對原始資料，不猜測轉換。這些仍是來源仿單的資料，未換算成個人用量。

可用 `npm run data:check-labels -- "衛署藥製字第027569號"` 連線查公開資料，再重開資料庫、禁止外部請求以驗證離線重用；結果存於 `test-results/label-reuse-check.json`。

## 匯入藥品外觀 CSV

從 [TFDA 藥品外觀資料集（9120）](https://data.gov.tw/dataset/9120) 取得 UTF-8 CSV 或包含單一 CSV 的 ZIP，執行：

```powershell
npm run data:import-appearance -- "下載檔案所在路徑/42_2.csv.zip"
```

此命令只更新外觀資料表，保留原有藥品、交互作用及對話。欄位錯誤、重複字號或解析失敗會保留原快照；成功後原始檔案按 SHA-256 存入 `data/raw/`。重新匯入同一檔案不累加重複紀錄。`data:sync` 更新其他來源時不會刪除外觀資料。

2026-09-19 匯入的 `42_2.csv.zip` 有 6,318 筆，6,294 筆以許可證字號連結主檔，24 筆僅有外觀紀錄且明示缺少成分。CSV 本身只有圖片網址；以下圖片索引流程另行下載參考圖。本機 OCR 只讀文字與刻字，顏色、形狀可手動補充。文字／外觀比對及本機報告不呼叫外部查藥 API。

## 本機藥錠照片比對

採用 DINOv2 Small 的量化 ONNX 模型，使用 CPU 擷取照片特徵，再搜尋本機 SQLite 圖片索引。不需要 Gemini 金鑰、Ollama 或外部推論 API；原有 OCR、查藥與報告流程保留。

可在「收錄與管理已核對的藥錠照片」補充自己的參考圖：先搜尋並確認品項，選擇對應許可證、填寫照片來源及核對依據，再明確勾選後收錄。可加入同一品項的不同面，誤收時可停用；來源會與官方照片分開標示。自存照片放在 `data/vision/personal-pills/`，不加入 Git 或公開資料包，官方索引不變。詳細操作與限制見[本機照片收錄](docs/vision.md#收錄已核對的藥錠照片)。

收錄是增加人工核對過的參考照片，不是自動學習未知藥品或完成模型訓練。一般查詢不保存照片，亦不會把 AI 候選自動加入圖庫；新增照片是否改善其他實拍的候選召回，仍需另行驗證。

先同步藥品主檔、匯入外觀 CSV，再執行一次：

```bash
npm run vision:prepare
npm run vision:index
```

`prepare` 首次需要網路，下載固定版本的模型與 [Pill Detective TW](https://github.com/liangRXdev/pill-detective-tw) TFDA 圖片鏡像；不執行鏡像專案程式碼。每次核對預期 SHA-256，已存在但損壞的檔案會重新下載；下載斷線、大小超限或校驗失敗不覆寫既有檔案。更新固定版本時也必須重新核對預期雜湊。

`index` 逐張核對許可證、原圖網址及 SHA-256，建立特徵索引；CPU 建置可能需要數十分鐘，可重跑接續已完成項目。圖檔、模型、來源與授權保存在 `data/vision/`，不提交到 Git。重匯外觀資料後請重新執行 `vision:index` 並重啟服務。

若已用 `vision:originals` 補存官方圖片，再執行 `vision:index` 也會補入鏡像未收錄、目前來源仍相符的藥錠／膠囊圖片；已存在的鏡像與特徵保持。來源明示為液劑、粉劑、顆粒、糖漿等品項不加入藥錠比對，仍能以名稱查詢及看圖。整批完成後才發布，缺檔、損毀或推論失敗會保留上一份索引。這是補齊參考圖涵蓋，並非提升模型本身的辨識準確率。

日常比對只在目前應用程式的後端推論：本機啟動時就在此電腦執行；部署遠端時，照片會送到那台後端。照片只用於當次處理，不寫入圖片索引或對話資料庫。模型與已索引的參考圖備妥後，此比對流程不需網路。這不是已完成的手機離線 App。

- 每次 1–2 張同一種藥的正反面，支援 JPEG、PNG、WebP；單檔 8 MB、合計 12 MB，最多 2 分鐘，可取消。一次處理一筆；其他請求明確提示稍後重試。
- 先裁切單顆藥、保留完整輪廓與刻字。DINOv2 是通用圖片特徵模型，沒有針對本專案藥品另行訓練；藥盒另用包裝圖庫，藥袋文字使用 OCR。
- 兩張照片分別對照同品項的最佳參考圖，再合併排序；刻字完全相符優先。相似度門檻是檢索規則，不是經校準的正確率，也無法保證偵測出混拍的不同藥。
- 一律顯示待核對候選，不自動確定藥名、成分、用法或劑量。資料庫缺圖、背景干擾、外觀相似、不同廠牌與拍攝品質都會影響結果；需正反面、刻字、藥袋及藥師共同核對。

可執行 `npm run vision:check` 進行實際模型的離線整合檢查；它使用參考圖旋轉／壓縮後的測試圖片，結果存至 `test-results/vision-smoke.json`，**不是獨立真實照片的準確率驗證**。詳細版本、API、授權見 [docs/vision.md](docs/vision.md)。

參考圖刻字太小時，可用 `npm run vision:originals -- --limit=20` 從本機資料列出的 TFDA 官方網址補存較清楚版本。點圖放大會優先讀取本機清晰圖，可選 2／4 倍或點兩下圖片放大該處；這項改善供人工對照，不改寫 CV 特徵或宣稱提高辨識準確率。

只想補上尚未存本機的圖片，可執行 `npm run vision:originals -- --missing-only --limit=1000`；會略過已有縮圖或清晰圖的網址，保留原取得日期。支援官方 UUID 及 `_img_1` 等編號格式，只下載目前許可證列出的原網址。完成後重新搜尋即可離線對照；已打開的舊報告可重新查詢取得圖片狀態。首次下載需網路，來源失效會記錄，不捏造替代圖。

藥錠另有選用的「Ollama 外觀輔助」：使用已安裝的本機視覺模型讀取刻字、形狀與顏色，先讓使用者修改核對，才搜尋本機資料。它不自動判定藥名、不改動 CV 排名；一般 CV／OCR 與年齡案例仍不需 Ollama。模型需求、照片處理及限制見 [圖片功能說明](docs/vision.md)。

在藥錠照片模式補充完整一面刻字，現在會同時查本機外觀資料，避免正確刻字的品項被圖片門檻漏掉。候選標明是照片相似、刻字相符或兩者皆有；同刻字有多款藥時顯示總數，可展開完整搜尋，仍需核對品名與規格。

## 藥盒圖片比對與收錄

「藥盒照片比對（本機 CV）」會直接擷取圖片特徵，搜尋 `data/vision/packages/` 的獨立 SQLite 索引；不呼叫 OCR、Gemini 或 Ollama。候選顯示實際收錄的藥盒參考圖，可點圖放大；需要文字時再選 OCR 輔助。

在頁面的「收錄已知藥盒」填寫本機資料中的完整品名、照片來源，核對並勾選確認後可存入上方照片。也可執行 `npm run vision:import-package -- "完整品名" "照片路徑"`。只接受與 TFDA 主檔完全相同的品名，保留全部同名許可證候選；不以包裝正面猜選其中一張許可證。重複收錄相同圖片不累加。藥錠索引重建不會覆寫藥盒索引。

也可從「確認並分析 → 藥品說明書 → 臺灣官方仿單與外盒 → 查看與保存外盒」保存官方圖片／PDF。首次下載需連線，之後可離線放大查看；PDF 保留全部頁碼，逐頁核對品名、規格與許可證後才加入藥盒比對。官方檔案也可能有舊版或規格錯植，有疑義的頁面不要啟用。這些檔案另存於 `data/vision/official-packages/`，不自動下載全庫、不呼叫 Gemini 或 Ollama。詳見[外盒保存流程](docs/本機仿單索引.md)。

開發環境曾用使用者提供的「普拿疼伏冒加強錠」1 張藥盒照片、2 筆同名許可證連結測試。這張私人提供的照片不包含在公開下載內容，**下載後的藥盒圖庫初始為空**。包裝、改版與規格需自行拍攝或取得可用來源後逐筆核對收錄。一般查詢不會自動儲存照片，只有明確收錄才寫入圖庫。

`npm run vision:check-package -- "藥盒照片路徑" ["其他照片路徑"]` 執行禁用外部 fetch 的實際模型測試，結果見 `test-results/package-smoke.json`。原圖與其旋轉／壓縮版本測試只驗證接線與檢索，不能當成獨立實拍準確率。

## 本機 OCR

藥盒、藥袋及藥錠照片使用官方 PaddleOCR.js 0.4.2、PP-OCRv5 mobile 偵測與辨識模型，在瀏覽器 Worker 讀取文字。包裝小圖沿用等比例放大；藥錠先讀原尺寸，過大時縮至最長邊 1280。小於 1280 的藥錠照片再放大補讀小字，有文字時提供「原尺寸結果／小字補讀結果」切換，各自保留文字、人工校正與照片位置，不依信心分數替換或混合兩組讀法。原尺寸有文字時優先顯示；補讀空白仍保留原結果，原尺寸空白才先顯示有文字的補讀結果。PDF 沿用 Tesseract.js，由 PDF.js 將每頁轉為圖片後辨識。兩條路徑都不把檔案傳送到後端或雲端，校正後選取的查詢文字才送到本機資料庫，不呼叫 Ollama 或 Gemini、不需要 API Key。保留可編輯文字、低信心提示與原檔預覽，不會自動確認藥品或猜改不確定字元。

切換讀法後需重新勾選查詢文字，並清除舊候選；補讀結果仍算同一張照片，不增加 PDF 頁數。補讀失敗會提示並保留原尺寸文字；取消或逾時則停止整次辨識，不送出未完成結果。放大可能讀錯或漏掉原本能讀取的短刻字，請搭配位置核對或裁切近照，實驗範圍與結果見[視覺辨識實驗紀錄](docs/視覺辨識實驗紀錄.md)。

藥錠請先裁切到同一顆的一面，排除尺規及背景文字；同一面的刻字分成多行時，可核對後勾選 2–6 行合併查詢。重複字元不自動刪除，正反面與不同藥錠不要合併。已用裁切後的 K.B.T 開發照片驗證 SK／KBT 合併查到克瀉寧，但仍可能把 10 讀成 16；這不是已完成藥品身分辨識或準確率驗證。

照片 OCR 結果會保留文字位置與瀏覽器內的對照圖片。按每行的「查看位置」可標出讀取區域，勾選時以綠框提示；同樣的數字出現在刻字及尺規時，藥錠模式仍分別保留位置。任何文字修改都停用舊框線對應，避免將校正後的文字誤認為模型原本讀到的內容。位置只輔助人工排除背景，不會自行判斷藥品、刪除背景文字或提高文字辨識信心；PDF 沿用原有文字核對流程。

`npm run dev` 與 `npm run build` 會先執行 `ocr:prepare`，從已安裝套件複製引擎、繁中／英文語言模型與 PDF 字型到 `public/ocr/`。首次另從 PaddlePaddle 官方下載約 22 MB 的兩個 ONNX 模型，核對固定 SHA-256；之後沿用已驗證的本機檔案。`overrides` 固定 ONNX Runtime Web 1.24.3，與 SDK 內建 Worker 版本一致。建置後資源包含在 `dist/ocr/`，執行時不向 CDN 下載。首次載入模型較慢。這不表示整個網站已完成離線 PWA 支援。

照片比對沒有候選時，可按「這是藥盒／藥袋，讀取藥名」沿用照片切到 OCR。2026-09-19 實測使用者提供的 408 × 169 藥盒圖，讀出「伏冒」「普拿疼」，以「伏冒」查本機資料可看到「普拿疼伏冒加強錠」的兩筆許可證候選；「加強錠」的末字及小字仍有誤讀。這是單張案例驗證，不代表辨識準確率，候選仍需核對。

每次最多 4 檔、10 頁；單檔 8 MB、合計 12 MB。單次辨識上限 3 分鐘，可取消；密碼 PDF 或超出頁數會提示分批／解密，不默默跳過頁面。預設不呼叫 Gemini，失敗也不自動上傳；只有切換「Gemini 輔助」並按辨識時才送出所選檔案。

## 本機啟動

需求：Node.js 22.12 以上的 22.x 或 24.x、npm，以及首次下載資料與套件時的網路連線。建議使用 Node.js 24；現有桌面打包工具不支援 Node.js 20。

```bash
npm ci
npm run data:install
npm run dev
```

開啟 http://localhost:3000 。`data:install` 安裝已整理的固定展示快照；已備妥資料時略過此步驟。若想自行從來源建立或更新基本主檔，改用 `npm run data:sync`：下載 TFDA 官方 ZIP 與 DDInter 官方八類 CSV，建立 `data/drugs.db`。完整資料通過驗證後才發布 `data/raw/drug-datasets.zip` 離線包；下載中斷或來源格式錯誤保留原資料庫及備份。之後可用 `npm run data:sync -- --offline` 重新匯入，亦相容舊版九個散檔。尚未匯入也可啟動，但介面會顯示資料尚未載入，不會假裝查詢成功。

需要自訂設定時，把 `.env.example` 複製成 `.env`：

- `DRUG_DB_PATH`：藥品資料庫位置，預設 `data/drugs.db`。
- `VISION_DATA_DIR`：本機視覺模型、參考圖與索引位置，預設 `data/vision`；下載、建索引與服務需使用同一路徑。
- `CHAT_DB_PATH`：對話資料庫位置，預設原有的 `medsafe.db`。
- 服務啟動時以上相對路徑及 `.env` 均以專案目錄為準，不受啟動命令所在的資料夾影響；絕對路徑保持不變。缺少的對話資料夾會自動建立。
- `PORT`：預設 `3000`，`0` 自動選擇可用埠；啟動訊息會顯示實際網址。`HOST` 預設 `0.0.0.0`，設為 `127.0.0.1` 可只接受本機連線。
- `OPENFDA_API_KEY`：選用的 openFDA 免費金鑰，只由後端讀取。
- `OLLAMA_API_BASE_URL`：後端可存取的 Ollama 網址，預設 `http://localhost:11434`。
- `OLLAMA_MODEL`：實際使用並檢查是否已安裝的模型，預設 `llama3.2:3b`；可改為電腦已安裝的模型名稱。
- `OLLAMA_TIMEOUT_MS`：本機模型完成回覆的等待上限，預設 300000（5 分鐘），避免 CPU 推論較慢時在 90 秒被中止。介面會分別顯示逾時、服務未啟動、缺少模型與模型執行失敗。
- `OLLAMA_THINK`、`OLLAMA_CONTEXT_SIZE`：選用的思考模式與上下文大小；本機 Qwen 3.5 可使用 `false` 與 `4096` 減少等待，實際速度仍依硬體與內容長度而定。
- `VITE_GEMINI_API_KEY`：僅供本機開發選用，會嵌入前端程式；共用部署請留空，讓使用者在介面輸入自己的金鑰。介面金鑰僅保存在頁面記憶體，重新整理後清除。
- `VITE_GEMINI_MODEL`：金鑰測試、文字與照片／PDF 辨識共用同一模型，預設 `gemini-3-flash-preview`。Google 提供此模型的免費層，但實際可用額度取決於專案；修改後須重新建置前端。遇到 429 時介面會區分無模型額度及暫時限流，不將它誤報為金鑰無效。

Ollama 文字功能預設 `llama3.2:3b`，可先執行 `ollama pull llama3.2:3b`。藥錠照片使用本機 CV，文字／PDF 使用本機 OCR，Gemini 為選用輔助。所有文字功能只使用選定引擎，失敗時不自動切換；CV／OCR 也不自動上傳雲端。Ollama 依後端設定連線，選用遠端服務或 Ollama 雲端模型時，不應視為離線處理（[官方說明](https://docs.ollama.com/faq#does-ollama-send-my-prompts-and-answers-back-to-ollamacom)）。藥物報告的查詢摘要直接依資料狀態生成，不呼叫模型。

## 檢查與建置

```bash
npm run lint
npm test
npm run build
```

`lint` 執行 TypeScript 型別與未使用程式碼檢查。測試使用人工測試資料、記憶體資料庫與獨立暫存資料庫，不覆寫使用者資料。

正式模式需設定 `NODE_ENV=production` 後執行 `npm start`；Windows PowerShell：

```powershell
$env:NODE_ENV = 'production'
npm start
```

`npm run preview` 只有 Vite 靜態預覽，不能取代 Express API。

`GET /api/health` 顯示服務與四個資料來源的載入狀態；`needs_data` 表示服務已啟動但仍缺資料，`ready` 只表示資料已匯入，不代表醫療資料完整或 AI 模型可用。`dataSetup` 區分暫存／磁碟資料及首次安裝、需要重啟、既有資料夾或自訂路徑；不回傳實際檔案路徑。未知 API 回傳 JSON 404，缺少建置檔或連線埠衝突會直接說明啟動失敗。

備妥資料與圖片索引並建置後，可執行 `npm run runtime:check`：從另一個目錄啟動正式版，以獨立暫存對話資料庫驗證資料路徑、本機搜尋與圖片，不寫入既有對話。結果保存於 `test-results/runtime-check.json`。

## Docker

```bash
docker compose up --build -d
docker compose run --rm app npm run data:sync
```

`data/` 會掛載到容器，保存藥品與容器版對話資料庫。本機原本的 `medsafe.db` 不會自動搬移。首次啟動 Ollama 容器會下載模型。

Cloud Run workflow 保留為手動觸發，推送程式碼不會自動部署。執行前須配置 GCP secrets 並規劃 SQLite 持久儲存；一般容器本機檔案不能當成可靠的跨實例資料庫。PWA manifest 與圖示由本機提供，但未實作完整 Service Worker 離線安裝流程。

## GitHub 原始碼與本機資料

儲存庫包含程式、鎖檔、測試與說明文件；`.env`、金鑰、對話資料庫、`data/` 下載／上傳資料、模型、`test-results/` 及 `release/` 安裝包均不提交。公開參考資料另以 Release 資料包提供，包含已準備的 SQLite、模型、藥錠參考圖及來源說明；不包含聊天紀錄與私人上傳照片。首次使用請依[下載與啟動指南](docs/GitHub下載與啟動.md)準備。生成的統計報告保留在本機，文件中的 `data/reports/` 路徑需執行對應檢查後才會出現。

分享 Windows 安裝包時須另行核對該次打包與原生啟動結果，不能把原始碼推送成功當成桌面版驗證通過。

## 歷史桌面實驗（本機網頁不需要）

目前維護與使用目標是 VS Code／終端機啟動的本機網頁，以下僅保留既有實驗與程式供參考；不需執行這些指令，也不以桌面驗證作為網頁版完成條件。

備妥上述資料後，`npm run electron:build -- --dir` 建立可執行目錄，`npm run electron:check` 檢查實際打包服務、圖片模型與重啟保存。`npm run electron:build` 產生 NSIS 安裝檔。Electron 會自行啟動本機服務、使用可寫入的使用者資料目錄，不需要另外執行 `npm start`。本機藥品查詢與案例不需模型金鑰，自由問答仍需 Gemini 或 Ollama。

原生套件與資料放在獨立打包目錄，不將開發者金鑰、聊天紀錄或自訂藥盒照片帶入安裝檔。詳細路徑、更新與驗證限制見 [桌面版說明](docs/桌面版.md)。

## 主要程式

- `src/App.tsx`：聊天、對話管理與症狀照護頁。
- `src/components/MedicationPanel.tsx`：藥品確認、資料報告與來源介面。
- `src/services/medication-ai.ts`：候選藥名辨識及檔案格式處理。
- `src/services/http.ts`：共用 API 請求與錯誤處理。
- `src/services/gemini-client.ts`：共用 Gemini 模型、金鑰與錯誤訊息處理。
- `server/sessions.ts`：對話資料庫升級與 API；保護手動標題、拒絕寫入已刪除的對話。
- `server/ollama.ts`：Ollama 代理、可設定的回覆等待上限與錯誤分類。
- `server/medications/`：資料庫、官方來源串接、匯入與 API。
- `server/vision/`：本機圖片特徵擷取、索引檢索與圖片 API。
- `src/components/VisionResults.tsx`、`PhotoCropDialog.tsx`：候選圖片核對與裁切。
- `shared/medication.ts`：共用資料型別、狀態文案與報告格式。
- `scripts/sync-drug-data.ts`：官方資料更新。
- `tests/medications.test.ts`：配對、資料完整性與錯誤處理測試。
- `tests/sessions.test.ts`：對話儲存、舊資料庫升級、AI 引擎選擇與請求失敗的回歸測試。
- `tests/ai-selection.test.ts`、`tests/ollama.test.ts`：選定引擎失敗、空回覆、已配置金鑰時不改送其他引擎、取消與 Ollama 連線狀態的檢查。
- `tests/gemini.test.ts`：共用模型、金鑰驗證、零額度與錯誤訊息的回歸測試。
- `tests/ollama.test.ts`：本機模型逾時、斷線、缺少模型及文字功能的錯誤回報測試。
