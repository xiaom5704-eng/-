# 藥品資料來源與對照規則

這份文件記錄目前程式的資料來源與實作邊界。匯入的資料庫與原始下載檔案不提交到 Git。

## 本機藥名與規格搜尋

一般關鍵字沿用品牌標點、全半形、簡繁字形與分詞搜尋。規格由完整數字及單位一起擷取，支援與中英文藥名連寫，避免 `1 mg` 分開後錯用許可證中的 1。只索引中文及英文品名，不從廠商、許可證、適應症或用法用量推測產品規格。有主檔時以主檔規格為準；只有外觀紀錄時才使用該紀錄品名，並保留缺少主檔的提示。

- 同一單位的文字寫法可查詢：mg／毫克／公絲、g／公克／克、mcg／ug／μg／微克、mL／毫升／公撮、L／公升／升，以及百分號。這些是搜尋拼寫，不改動来源原文或成分身分。
- 簡單小數只整理無意義零，例如 `.4` 與 `0.40`；不使用浮點計算，不將 1 mg 改成 1000 mcg。分母保留，`0.4mg/mL` 對照 `0.4mg/1mL`，不對照 `0.4mg/5mL` 或單獨 `0.4mg`。
- 範圍、分數、千位逗號、正負符號、科學記號與額外比率保留寫法，不計算或移除分隔符。例如 `1-5mg` 不等於 `15mg`，`1/2mg` 不等於 `2mg` 或 `0.5mg`，`1,000mg` 不當作 `1.000mg`。不識別的單位仍依一般文字搜尋，不承諾已完成規格解析。
- 手動搜尋與掃描結果的 `strength` 欄位套用相同條件；刻字仍使用原有完整刻字規則，不經規格或簡繁轉換。單位／數值未記載於品名的品項不會列入規格結果，畫面提供改用藥名查詢的說明。

這是候選檢索，不能證明複方每一個數值屬於哪個成分、劑型相同或適合病人。結果保留許可證、註銷狀態及原始品名，須人工核對。索引版本 4 在啟動時以交易重建，來源資料不變，舊分頁版本失效並提示重新搜尋；更新來源時同步更新索引。

## 更新與資料完整性

```bash
npm run data:sync
```

固定從官方網址下載，不接受前端提供任意下載網址。完整且通過匯入驗證的九個來源保存在單一 `data/raw/drug-datasets.zip`，附來源網址、下載時間、大小及 SHA-256；雜湊用來偵測備份損壞，不是官方數位簽章。資料庫由 `DRUG_DB_PATH` 控制，預設 `data/drugs.db`。

已經成功同步時可執行 `npm run data:sync -- --offline` 重新匯入，完全不連外。優先使用上述完整資料包；既有安裝尚無資料包時，仍可讀取 `data/raw/` 的 TFDA ZIP 與全部八個 CSV。若新資料包存在但校驗失敗，會明確報錯，不偷偷改讀舊版散檔；可重新線上同步修復。外觀 ZIP 不會被同步命令覆寫。

更新會先完整下載、驗證欄位與風險等級，再以 SQLite transaction 更換兩個來源，並一次發布整個離線資料包。下載中斷、解析錯誤或資料衝突均保留原資料庫及離線包；發布失敗也會回復資料庫。下載逐塊限制大小，未完成的暫存檔不供離線匯入。若程序恰在發布後、資料庫提交前被中斷，資料庫由 SQLite 回復，離線包仍為完整有效版本，可再用 `--offline` 完成匯入；不宣稱資料庫與檔案系統共用原子交易。

TFDA 重複許可證以許可證字號合併；中文品名缺漏時保留英文名。複方成分依官方 `;;` 分隔符拆分。

介面顯示匯入時間、筆數與涵蓋範圍。匯入日期不是資料本身的更新日期。DDInter 下載資料只是網站公開下載範圍，不能宣稱完整覆蓋所有藥品或所有交互作用；CSV 僅有成分 ID、名稱、配對及風險等級，不含機制與處置全文。

## 對照與查詢

1. 藥錠照片預設使用本機 DINOv2 相似圖片檢索，列出最多 8 個待核對候選；完整流程與限制見 [vision.md](vision.md)。藥袋／外盒照片使用本機 PaddleOCR，PDF 文字與藥錠刻字使用 Tesseract.js；PDF.js 逐頁轉圖後辨識。結果保留原文與信心提示，使用者校正後查本機。OCR 不判讀顏色／形狀、不猜成分、不把 O／0 等不確定字元互換。Gemini 是明確選用輔助，僅抄錄可見名稱、規格、劑型，或清楚可見的藥錠顏色、形狀、刻字；禁止由外觀猜藥名。
2. 本機 OCR 每次以使用者選取的一行比對，Gemini 輔助辨識後批次比對最多六組；完整刻字精確比對、正反面不分順序，字母大小寫、空白與全形標準化，但不作部分刻字或相似編號替換。提供的顏色與形狀條件必須同時成立。多個候選保留、回傳總筆數，每頁二十筆且可翻頁，不自動選中；翻頁保留原查詢條件與已確認藥品。使用者可手動輸入相同特徵，不用 AI。名稱與外觀同時提供時不放寬衝突條件。
3. 後端只接受來源和 ID，重新讀取權威記錄，不信任前端傳入的成分。
4. 預設本機模式，TFDA 成分以完整名稱、官方 `(EQ TO ...)`、已核對別名及本機保存的官方 RxNorm 精確對照尋找 DDInter 成分，無法對照就保持未知。使用者線上補查或管理者執行 `data:enrich` 時，才以 RxNorm `search=0` 和 IN／PIN 概念、唯一 IN 關係核對並保存版本、日期與來源。不任意移除鹽類或括號內容；多個 RxCUI、對照失敗或一個成分對應多個 IN 時不自動猜選。詳見[本機成分對照](本機成分對照.md)。
5. DDInter 以雙向排序配對查詢；複方內與跨品項配對皆檢查。重複成分另外標示。這是成分層級篩查，尚未按劑型、途徑或個人狀況判定。
6. openFDA 依標準成分及已查證的 RxNorm 匹配名稱搜尋，例如已確認的 maleate 名稱關係。每個仿單成分必須唯一對應本次的一個成分群組，完整集合數量相同，不接受多出成分的複方，也不任意移除鹽類字尾。每頁 100 筆，最多 5 頁，顯示最多兩個不同 SPL Set 的相符仿單；達到筆數限制或找到兩份便停止。若尚未篩選全部且沒有候選，狀態為 `incomplete`，不是查無。這些仍是相關美國仿單，未核對規格／劑型／用途，不能視為所選臺灣產品的仿單。分頁參數見 [openFDA 官方文件](https://open.fda.gov/apis/query-parameters/)。
7. 仿單段落保留全文，避免截掉限制條件；包含來源提供的兒童、高齡者與特定族群使用資訊。資料缺少獨立的兒童或高齡者段落時會明示，不計算個人劑量。欄位依 [openFDA 官方文件](https://open.fda.gov/apis/drug/label/searchable-fields/)。

外部查詢有連線逾時，成功原始回應快取最多 24 小時。篩選後仿單另存 `label_registry`，依標準成分、RxCUI 及已核對名稱範圍區分，保留取得日期、原查詢、檢查筆數、來源資料集更新日及個別仿單 ID／SPL Set ID／version／effective_time。欄位來源見 [openFDA 欄位文件](https://open.fda.gov/apis/drug/label/searchable-fields/)。舊 HTTP 快取缺取得時間時會重查，不自行補成今天。

本機分析零外部請求即可重用已保存結果；超過 7 天提醒更新，此為專案門檻，不是醫療有效期限。線上更新失敗仍保留舊資料及原時間，附上 `labelLookup.refresh: failed`；成功查無則取代舊結果。openFDA 的 404 `NOT_FOUND` 只表示此查詢未匹配。HTTP 錯誤與異常格式不保存為查無，無舊紀錄可用時顯示來源不可用。UI、Markdown 與多語摘要均保留更新失敗、來源日期及未知狀態。

本機報告在沒有可重用紀錄時使用 `labelStatus: not_requested`；若保存過成功或查無結果，則呈現該次結果及取得時間，與未查、成分未對照、來源不可用、只完成部分篩選分開。本機模式拒絕需要線上解析的 RxNorm 選取，不暗中呼叫外部 API。外觀 CSV 不含成分、交互作用與劑量；只有成功連結主檔的記錄才有成分可供分析，未連結品項不補造資料。

外觀匯入需包含官方十二個欄位，UTF-8 解碼、CSV 欄位、許可證唯一性與大小通過驗證後才交易更新；ZIP 只在記憶體解壓，不將壓縮包路徑寫入磁碟。保留原始 `;;;` 多值資料供核對，比對索引將這些值拆開；同一許可證可能含多個外觀，因此特徵相符仍不是唯一身分證明。原始圖片只接受 HTTPS 食藥署網域，點擊可放大並核對品名、字號及外觀文字。多張圖可切換；缺圖或連線失敗會提示，不以其他藥品圖片代替。一般搜尋、外觀比對、案例與報告也會使用已下載且符合目前許可證及原圖網址的本機參考圖，顯示圖片不必載入推論模型；尚未下載的圖仍需連線。介面分別標示全部／部分已存本機與需要連線，保留官方原圖連結。CSV 匯入本身不下載圖檔，另由 `vision:prepare`、`vision:index` 建立本機圖庫。

藥名搜尋使用獨立索引，支援全半形、名稱標點及以空白分開的多個關鍵字，例如 `KBT`、`普拿疼 加強`；所有關鍵字都須符合。完整許可證及完整品名優先，品牌前綴其次。此寬鬆處理只用於候選搜尋，不改寫來源名稱、成分或交互作用的精確對照。分頁攜帶資料版本，更新來源後會要求重新查詢，避免混用兩次匯入的結果。

### 已核對的名稱差異

`server/medications/verified-names.ts` 保留少量經來源核對的明確別名，核對日期為 2026-09-17。`CAFFEINE ANHYDROUS` 依 [FDA GSRS caffeine 記錄](https://precision.fda.gov/ginas/app/ui/substances/3G6A5W338E) 對應 caffeine；不套用到 caffeine citrate 或其他水合物。`ACETAMINOPHEN FINE` 與 `ASCORBIC ACID (COATED)` 只在衛署藥輸字第023784號內，依 [TFDA 公開的 2016 版仿單](https://www.fda.gov.tw/tc/includes/GetFile.ashx?id=f636700104403134386&type=1) 的 acetaminophen、Vitamin C 成分表對照 acetaminophen、ascorbic acid，不將該產品依據推廣成通用字串清理規則。它們只用於成分識別，不代表含量、製劑或用法等同；原始名稱與核對連結在畫面及儲存報告中保留。此仿單連結標示版本，不聲稱為最新版。

查詢結果優先顯示重複成分與已查得的交互作用，其餘配對可展開查看，並區分同一品項內的配對。摘要按狀態合計未知配對；完整報告仍保留每組原始結果。資料集中缺少的成分保持未對照。

結果頁分為「用藥提醒」與「藥品說明書」，查詢完成會移至結果標題。同一成分配對的重複呈現會合併，但不同風險、不同狀態、複方內與跨藥品紀錄分開；所有原始配對均保留在明細與儲存報告。乙醯胺酚、咖啡因的中文名稱僅用於顯示，依 [食藥署名稱說明](https://www.fda.gov.tw/TC/PublishOtherEpaperContent.aspx?id=1538&r=251002883&tid=4980) 核對，不參與後端成分匹配。仿單頁優先呈現 TFDA 中文適應症及已核對的臺灣仿單連結，美國原文按需展開，仍保留完整段落與適用範圍限制。

## AI 與資料流

- 照片／PDF：本機 CV 將照片送往目前應用程式後端，只在記憶體處理；OCR 模式只在瀏覽器讀取文字，校正後選取的文字才查本機後端。只有切換 Gemini 輔助並按辨識才送至 Gemini；CV／OCR 失敗不自動轉送。原檔不儲存到對話資料庫。
- 手動搜尋：TFDA 在本機查詢；RxNorm 搜尋會把藥名送到 NLM。
- 資料報告：預設只讀本機資料；按「補查線上仿單與標準名稱」才將成分名稱送到 RxNorm、openFDA，不傳送照片、對話或病人資料。
- 查詢摘要：直接將查詢狀態依固定文案呈現，支援繁體中文、英文、日文與越南文；不呼叫模型，不額外傳送資料。原始藥名與仿單內容保持原文。
- 儲存報告：將來源、匯入時間、限制與原文一起存入選定對話；新增的兩則訊息以單一 transaction 儲存。摘要與來源內容一併保留。

一般聊天與症狀頁仍是模型生成的資訊，並非每次自動查詢藥品資料。兩個入口使用相同的全年齡照護提示詞，參考填寫的年齡及當前對話，不預設為嬰幼兒。藥品問題引導至查詢頁、保留來源限制，不自行計算任何年齡的個人劑量；提示詞本身不能保證模型正確。

## API

- `GET /api/medications/status`：資料快照狀態及主檔實際非空白劑型 `dosageForms`。
- `GET /api/medications/search?q=...&source=tfda|rxnorm&offset=0`：本機每頁 20 個候選，回傳 `page: { offset, limit, total, hasMore, revision }`，後續翻頁帶入 `revision`。來源版本變更回傳 409，重新從第 1 頁查詢。RxNorm 線上搜尋僅提供最多 20 個候選，`total: null`，不宣稱完整結果，也不支援翻頁。
- `POST /api/medications/match`：`{"observations":[{"name":"","strength":"","dosageForm":"","appearance":{"shape":"圓形","color":"白","imprints":["FY T061"]}}]}`，1–6 個觀察結果；只查本機，回傳候選、符合筆數、`page` 及限制。翻頁時只傳一筆觀察結果，在根層加入 `offset` 與 `revision`。
- 本機 `/search` 可附 `dosageForm`（最多 120 字）；與 `/match` 的劑型採同一篩選。主檔細分類精確比對，僅支援明列的中英文名稱對照，不合併內服／口服、膜衣／腸溶／特殊釋放劑型，不從廠商、品名或外觀特殊劑型補猜。未知條件回傳零候選及校正說明，留空取消劑型限制；RxNorm 不接受此條件。來源詞彙參考 [TFDA 劑型分類文件](https://www.fda.gov.tw/tc/includes/GetFile.ashx?id=f636694183792583215) 的中英名稱，不使用其製造涵蓋範圍推論臨床等效。資料更新時同步失效劑型清單快取。
- `GET /api/medications/reference-images/:sha256.webp`：提供已下載、仍對應目前品項與來源網址的藥錠參考圖；沒有收錄、檔案缺少或來源關聯失效時回傳 404，不補用其他圖。
- `POST /api/medications/report`：`{"drugs":[{"source":"tfda","id":"許可證字號"}],"mode":"local"}`，1–6 個不重複品項。`mode` 預設 `local`，明確指定 `online` 才補查外部來源。
- 每筆品項的 `labelLookup` 顯示保存紀錄的 `retrievedAt`、`sourceUrl`、`sourceUpdatedAt`、`reused`、`refresh`、`stale`、`scanned`、`total`、`complete`；`refresh` 為未要求更新、HTTP 快取、取得新資料或更新失敗，分別是 `not_requested|cached|succeeded|failed`。`labelStatus: found` 僅代表存在相符的參考資料，不代表本次連線成功、資料最新或用藥適用。
- `/report` 可附 `patient: { age: { value: "1", unit: "months" }, premature: "unknown" }`；單位為 `years|months|days`，早產狀況為 `unknown|yes|no`。來源規則只覆蓋有限品項，結果放在 `safety`，不改寫 `interactions`。
- `POST /api/medications/demo`：載入五款教學示範品項並做本機分析；許可證或完整成分集合不符時回報 409。回應包含 `demo` 選品假設，並非原處方身分確認或照片辨識結果。詳見 [展示指南](比賽案例展示指南.md)。
- `POST /api/sessions/:id/medication-report`：`{"content":"Markdown 報告"}`，原子儲存到既有對話。

## 驗證

`npm test` 使用明確標示的人工測試資料與記憶體資料庫，涵蓋匯入回復、反向配對、複方／重複成分、未對照、未匯入、外部錯誤、仿單成分篩選及 PDF MIME。測試資料不會混入應用資料庫。實際來源連線應另外以本機服務檢查；AI 輸出品質不由這些測試保證。
