# 本機藥錠圖片比對

本功能是「相似圖片檢索＋人工核對」，不是經臨床驗證的藥品身分判定。原本的藥品主檔、OCR、交互作用和仿單查詢流程沿用。

## 裁切與還原照片

照片下方的「裁切照片」可框選藥錠或文字，套用後可按「還原原始照片」恢復最初上傳的完整檔案；連續裁切不會覆蓋原圖。每張附件獨立還原，取消裁切則保留照片與現有結果。

裁切、還原、加入或移除附件會清除舊 CV／OCR／AI 外觀結果、刻字與候選搜尋，須重新辨識或核對；人工確認的藥品清單和報告保留。原圖僅在本次頁面記憶體保留一份，不另行上傳或存入對話；辨識及明確收錄照片時只使用目前預覽版本。移除附件或重新整理頁面後不保留原圖。

單檔 8 MB、合計 12 MB 的限制會預留原圖還原所需容量；縮小照片後再加入新檔，也不能使還原後超過此上限。此功能讓辨識失敗後容易重新選範圍，沒有改動圖片模型、門檻或完成實拍準確率驗證。

## 資料流與版本

1. 使用者上傳同一種藥錠的 1–2 張照片，可先在瀏覽器裁切並補充刻字。
2. 應用程式後端以 Sharp 校正方向、白底等比例縮放至 224 × 224；不作中心裁切，以免截去刻字。拒絕空白圖、過小圖、超限、動畫或不支援的格式。
3. Transformers.js 3.8.1 / ONNX Runtime CPU 執行 DINOv2 Small q8，取 384 維 CLS 特徵並正規化。執行時禁止遠端模型下載。
4. 對每張輸入圖，尋找每個品項的最佳參考圖；兩張輸入的相似度取平均。每張都需達到 0.60 才算通過圖片檢索門檻。填入完整一面刻字時，另查整份本機外觀資料，包含圖片低於門檻或尚無可用圖片特徵的品項；不替換 0／O 或接受部分刻字。合併後優先顯示刻字符合候選，最多 8 個，同時標示「照片相似」「刻字相符・照片未確認」或「照片相似＋刻字相符」。同刻字超過頁面顯示數時，可展開既有完整本機搜尋及分頁。門檻未經獨立實拍資料校準，不是醫療辨識正確率；刻字也是使用者提供的線索，不能唯一認定藥名。
5. 候選品名與成分從本機 TFDA 資料庫重讀，圖片鏡像或模型不提供成分判定。同張照片若對應不同許可證，保留不同候選。仍需使用者核對並確認，才進入既有報告流程。
6. 藥盒另用「藥盒照片比對」，可從藥錠結果直接切換並沿用附件。需要文字核對時，仍可按「這是藥盒／藥袋，讀取藥名」，使用本機 PaddleOCR，不會將藥盒當作藥錠刻字。

圖片鏡像僅作為下載來源，不執行其程式碼，也不把鏡像商品名直接當權威主檔。只納入與目前外觀 CSV 的許可證及原圖 HTTPS 網址一致、SHA-256 正確的照片；排除外觀欄位標示液劑、粉劑、顆粒或散劑的項目。CSV 缺少照片、版本不同或無法連結的項目不硬配。

「輸入刻字與外觀查本機資料」及 Ollama 外觀核對表單使用當前資料庫的形狀／顏色選項，顏色可點選複選、再次取消或手動修改。資料庫用字直接顯示，例如「粉」，不自動推定其他色名相等。形狀選項也包含液劑、粉劑及顆粒劑，供文字欄位篩選；這些選項不會把品項加入藥錠 CV 圖庫。匯入新版 CSV 後重新讀取資料狀態，選項隨快照更新；既有刻字、名稱及多色同時符合條件不變。

## 建立與更新

先備妥 `data/drugs.db` 及外觀 CSV，執行 `npm run vision:prepare`、`npm run vision:index`。可用 `.env` 的 `VISION_DATA_DIR` 指定資料目錄，兩個命令與伺服器應一致。第一次下載需要網路；後續模型與圖庫搜尋只使用本機檔案。

`data/vision/` 包含模型、WebP 圖片、SQLite 向量索引、原始 ZIP、逐檔模型雜湊、`ATTRIBUTION.txt`、模型及鏡像授權，以及 `index-failures.json`。重新建立期間持續使用上一份完整索引；新向量先寫入 `image_build_cache`，全部完成後才用單一 SQLite transaction 更新圖片列及版本。中斷、任何一張圖失敗或發布失敗都不覆寫既有索引；第一次尚無完整索引時仍需等待完成。失敗命令回傳非零，原因保存在 `index-failures.json`，修復後可重跑。下載使用固定版本；更新版本或前處理時需更改 `MODEL_VERSION` 並重建。

續建核對模型、來源網址、許可證、圖片 SHA-256、向量長度、有限數值及正規化後才沿用；有效圖片不重寫，新增或修復圖片先完整寫入暫存檔再改名。成功發布後清除建置快取，檔案路徑中的舊圖片不自動刪除。不要同時執行兩份重建：若其他程序已發布，較舊程序會拒絕覆寫，需重新執行。重建過程若變更正式模型設定，舊索引仍須符合伺服器要求的模型版本才能使用，不能跨模型混用向量。

`vision:prepare` 另核對程式內固定版本的預期 SHA-256，不再接受任何非空檔案作為成功快取。損壞檔案會重新下載，下載失败不覆寫原檔；模型或鏡像版本更動時，須一併重新查核預期雜湊。完整鏡像版本與雜湊保存於 `reference-provenance.json`。

外觀 CSV 的來源圖片更新後應重跑索引。服務依索引與資料版本更新快取，排除特徵格式錯誤及已失效的品項連結；查詢時再讀品項來源，避免接受前端造出的成分資訊。

2026-09-24 修正檔案可用性被舊快取綁住的問題：每次狀態檢查讀取一次圖片目錄，推論完成後再確認目前可用參考。缺失的圖片不列入可用數量或視覺候選，同名資料夾也不當圖片；還原原本索引對應的圖片後，按「重新檢查圖片庫」即可恢復，不必重啟或重新推論全部圖片。這適用藥錠及共用服務的藥盒圖庫，不是新增品項或新的辨識模型。正式圖庫仍為 6,142 張／5,787 品項，五張既有照片的候選與分數不變。

### 保存較清楚的官方參考圖

鏡像照片可能已縮小，藥錠刻字會流失。可執行 `npm run vision:originals -- --limit=20`，依本機許可證與外觀資料中的官方原圖網址逐張下載；加上 `--id=完整許可證字號` 可指定品項，可重複提供多個 `--id`。預設略過已保存項目，`--refresh` 才重新取得。命令從專案目錄解析設定，不因執行目錄改變而使用另一份資料庫。

若只要補齊「需連線」的圖片，可執行 `npm run vision:originals -- --missing-only --limit=1000`。此模式連已有本機縮圖的來源也略過，不與 `--refresh` 同用；可重跑續做，不重新取得成功項目的日期。官方網址支援 UUID 及 UUID 加 `_img_數字` 格式，仍須完全符合所選許可證的當前外觀紀錄。資料庫不存在時直接提示先安裝，不建立空庫。

圖片另存 `data/vision/originals/`：記錄許可證、原圖網址、原始與保存圖片的 SHA-256、解析度、取得時間及轉換版本。保存為 WebP 品質 95，最長邊上限 8192，不放大小圖；這是官方來源的衍生圖片，並非原始檔位元組副本。下載只接受目前品項列出的 TFDA 公開圖片端點，不跟隨轉址；單檔最多 50 MB、8,000 萬像素。失敗不覆蓋既有圖，連續三筆失敗會停止批次並保留已完成項目；結果在 `data/reports/reference-originals-*.json`。

搜尋、外觀核對、CV 候選及報告仍使用較小縮圖；點圖放大時優先讀取已保存的清晰圖，可按「放大 2 倍／4 倍」並捲動核對刻字。沒有 CV 模型或索引也能查看已保存的官方圖。品項或來源 URL 改變、檔案缺失後不再提供該圖片。新桌面包會帶入這些公開參考圖；舊安裝檔需重新打包才包含更新。

此流程只改善人工圖片對照，**不會自動改寫 CV 向量或提高辨識正確率**。原圖品質與藥錠位置裁切的檢索實驗另行驗證後才能更新正式模型。

### 藥袋欄位與查詢文字核對

藥袋／外盒 OCR 的一行文字可能同時包含品名、規格與用法。直接將整行當藥名搜尋容易漏查；現在依明確的藥名欄位前綴、用法／數量等冒號欄位，以及帶數字和單位的「每次／每日」文字，提出可展開的查詢建議。此整理只在瀏覽器執行，沒有新增模型或外部請求。

使用者先核對建議中的藥名及完整規格，再按「用核對後藥名查詢」。畫面保留原 OCR 文字、原位置和分出的欄位；編輯建議會清除舊候選，明示規格需重新核對。濃度分母、小數、範圍、分數和不確定字元不推測或換算。用法文字不轉成服藥建議，品項仍須人工確認。跨行、多個有標籤的藥名、沒有明確界線的自由文字不自動整理；刻字模式完全沿用完整刻字查詢。

2026-09-23 的人工文字图片經真實 PaddleOCR 後，含欄位的 Somin 2mg 整行原先零候選，核對建議後兩筆；Cypromin 0.4mg/mL 兩筆、普拿疼膜衣錠500毫克三筆，原文保持不變。這是流程測試，不是實拍藥袋的準確率。使用者提供的普拿疼伏冒加強錠照片仍可合併三行名稱查得兩筆；詳細證據在 `test-results/ocr-query-ui-proof.json`。

### 本機 OCR 讀刻字與合併查詢

「本機 OCR」選擇「單顆藥錠刻字」後，照片使用既有的 PP-OCRv5 mobile 模型，不需 Ollama 或金鑰。先讀原尺寸，最長邊超過 1280 才縮小；不足 1280 的照片另放大補讀小字。放大可能漏掉原本可讀的短刻字，因此保留原尺寸結果，補讀有文字時才提供兩組結果切換；不按信心分數自動挑選、不拼接不同讀法。原尺寸完全空白時先顯示有文字的補讀結果。請使用「裁切照片」保留一顆藥錠的一面，排除背景品名與尺規。系統尚未自動區分讀到的文字是否位於藥錠表面。

2026-09-28 增加小圖補讀：僅在上述兩次均無文字、且藥錠照片最長邊小於 224 像素時，另以最長邊 224 的等比例畫面辨識。補讀結果保留原圖位置對照、原尺寸切換及人工校正，不以資料庫中的藥名或刻字改寫模型輸出。已有文字的結果不被替換，藥袋／外盒與 PDF 不使用這一步。

固定 24 張開發／來源裁切圖，以修改前後的完整瀏覽器流程比對：原有 6 張非空結果逐欄保持，7 張由空白變為有文字，其餘 11 張仍空白，包含純色控制圖。小幅 Somin 裁切讀到 C、Fencaine 裁切讀到 FC／10，實際網頁可核對後查本機候選；其他圖仍有誤讀（例如 OL／1CO），因此「有讀到文字」不能當作讀字正確率或獨立實拍辨識率。

兩組文字各自保留校正與位置，切換後清除勾選及舊搜尋候選，請重新核對要查詢的行。補讀失敗保留原尺寸文字並提示；取消或逾時不交付半成品，可重新開始。每張照片仍只算一頁，藥袋／外盒及 PDF 流程不額外補讀。2026-09-22 的完整 Fencaine 開發照片原尺寸只讀到尺規；補讀可讀到藥錠的 FC／10，實際核對兩行位置後合併查得 031990。這是開發範例的文字查詢改善，不能當作獨立實拍的藥品辨識準確率。

核對文字後可勾選同一面的 2–6 行，再按「用完整刻字查本機資料」；CV 的 OCR 輔助則按「合併填入同一面刻字」後重新比對。重複行依位置保留，不刪除重複字元、不合併正反面，不猜改 0／O、1／I 或 10／16。辨識輸出不是藥品身分，候選仍需人工確認。

照片結果另附文字位置對照：灰框表示模型讀取的位置，選取的行顯示綠框，「查看位置」可單獨標出橙框。這能看出某行是否位於尺規或背景，但系統不自動替使用者判斷文字屬於哪顆藥。文字一經修改，不再沿用原位置；PDF 或没有有效位置資料的結果仍可校正與搜尋。預覽及位置只存在瀏覽器本次辨識狀態，不寫入藥品索引、報告或對話。

開發照片的裁切圖已讀到 SK／KBT，合併後在網頁找到克瀉寧；另一張 FC／10 仍可能誤讀成 FC／16。固定 32 張來源圖片的完整刻字單行符合數：原尺寸 5、僅放大 4、保留兩組時任一符合 7。多數仍未讀到，且可能讀到背景文字，不能將放大當成必定更準。這只是文字覆蓋比較，不是獨立實拍的藥品辨識準確率。測試方法及限制見[實驗紀錄](視覺辨識實驗紀錄.md)。

## API 與儲存

### 保存官方藥盒參考頁

已確認品項的「藥品說明書」可從 TFDA 本機索引下載指定外盒圖片或 PDF，保存後逐頁核對，再明確啟用照片比對。未核對、停用、來源／品項變更、檔案損毀或特徵失效的頁面不參與檢索；未核對及停用頁面仍可離線預覽。PDF 最多 8 頁且全部成功才保存，不只取第一頁。使用流程與限制見[本機仿單索引](本機仿單索引.md)。

`GET /api/medications/packages/official-references?drugId=許可證` 讀取本機狀態；`POST /official-references` 要求 `drugId`、`sourceUrl`、`indexSha256`，後端重讀當前主檔／索引並驗證網址。`POST /official-references/:key/enable` 要求 `confirmed: true`；`POST /official-references/:key/disable` 只停用比對。`GET /official-images/:sha.webp` 提供仍符合當前來源且通過雜湊核對的本機預覽，使用 `private, no-store`。

檔案另存 `data/vision/official-packages/`，不修改個人藥盒或官方藥錠索引。保存與 CV 共用推論佇列，使用相同 DINOv2 特徵及既有藥盒門檻。PDF.js 與明確安裝的 `@napi-rs/canvas` 在後端逐頁轉圖，字型與 CMap 使用本機套件資源，不執行 PDF 內的 JavaScript。

### 收錄已核對的藥錠照片

藥錠模式下展開「收錄與管理已核對的藥錠照片」。先搜尋藥名或許可證，核對候選並按「確認並分析」，再回到收錄表單選擇該品項。對照實物、原包裝／藥袋或藥師資料，確認上方 1–2 張照片都是同一品項的不同面，填寫照片來源與核對依據、勾選確認後才保存。不要把 AI 候選當作正確標籤；照片與來源文字勿包含病人個資。

只接受已有 TFDA 主檔、成分及明確錠劑／膠囊／丸劑分類的品項，依完整許可證連結，不因同名就連結其他產品。伺服器比較前端實際核對的品名、英文名、成分、劑型及製造商與當前主檔，推論完成後再核對一次；資料改變時要求重新搜尋確認。照片依既有大小限制解碼，校正方向、去除 EXIF 等中繼資料、最長邊不超過 1600，存成 WebP，沿用正式 DINOv2 的前處理與模型版本。

`data/vision/personal-pills/` 是獨立 SQLite 索引與照片目錄；不寫入官方索引或藥品主檔，亦不隨現有公開快照發布。相同照片與許可證重送不累加。每次查詢先排除停用、品項已變動、模型版本不符、向量錯誤、圖片缺失或雜湊不符的紀錄，再與官方參考圖一起按原本規則比對：每個視角尋找該品項最佳照片，兩個視角都須達到 0.60，門檻未降低。自存索引故障會顯示原因，仍可使用有效官方參考圖。

候選會額外顯示實際匹配的「使用者核對的本機照片 · 非官方」、來源文字及放大功能。「停用這張照片」立即排除後續比對及圖片供應，保留本機檔案與停用紀錄；重新核對並收錄相同照片可恢復。新增／移除附件、裁切照片或變更已確認品項時重設收錄表單，不能沿用之前的勾選。收錄可取消等待；若請求已完成，重新讀取自存照片即可確認狀態。

API：`GET /api/medications/vision/personal-references` 讀取紀錄；`POST` 同路徑要求 `images`、`drugId`、`identity`、`sourceNote`、`confirmed: true`，其中 `identity` 由共用的 `pillReferenceIdentity` 產生並由後端重讀主檔比對。`POST /personal-references/:key/disable` 停用，`GET /personal-images/:sha.webp` 只提供仍有效的收錄照片，使用 `private, no-store`。收錄與既有 CV／Ollama 共用推論佇列，120 秒上限，不自動切換雲端。

2026-09-27：新增九項測試涵蓋許可證隔離、取消、兩照片原子收錄、成分變動、照片損毀與恢復、停用、來源標示、跨官方／自存圖的兩面合併及 HTTP 流程；完整 311 項測試通過。實際模型在禁止外部 `fetch` 的隔離流程完成收錄／搜尋／停用，停用後候選與分數回復原值，官方索引雜湊不變。正式建置的隔離網頁完成搜尋、收錄、放大、比對及停用，390 px 畫面無水平溢出。測試照片由已知官方參考圖旋轉生成，**這是同圖回查與功能測試，不能當成獨立實拍準確率**。正式使用者圖庫未寫入測試照片。

### 選用：Ollama 讀取外觀，核對後查本機資料

在藥錠模式上傳照片後，可按「使用 Ollama 外觀輔助」。這一步只讀取形狀、顏色與刻字，不回傳藥名或成分，也不自動查詢或確認品項。結果先填入可編輯欄位，使用者對照照片、修正後，按「以核對後特徵查本機資料」才沿用現有外觀搜尋。搜尋仍要求全部所填條件符合，不會為了產生結果偷偷忽略刻字或顏色。

此選用功能需要啟動本機 Ollama，並將 `OLLAMA_MODEL` 設為已安裝且有 vision 能力的模型；預設文字模型 `llama3.2:3b` 不適用。開發機驗證使用現有 `qwen3.5:4b`，沒有自動下載模型。一般 CV、OCR 及一鍵年齡案例仍不需要 Ollama。影像呼叫方式依 [Ollama 官方文件](https://docs.ollama.com/capabilities/vision)。

`POST /api/medications/vision/observe` 使用與 CV 相同的 1–2 張圖片格式和大小上限，最多等候 180 秒，可取消。服務先檢查模型是否具備 vision 能力；只允許 loopback 或 Docker 的 `ollama-service`，拒絕遠端位址、轉址與標記為 cloud／remote 的模型。照片先去除中繼資料，在記憶體內轉為最長邊 1280 的 JPEG；不儲存、不建立索引、不送 Gemini。遠端部署時，照片仍會先送至該專案伺服器，這裡的「本機」指伺服器上的 Ollama。

模型可能誤讀或無法確認。空白、格式錯誤、混拍／不確定、資料不足、未啟動或文字模型會顯示原因，保留手動／CV／OCR 操作。這是協助輸入特徵的試用功能，未完成獨立照片集或臨床驗證，不能以模型回答取代藥袋、許可證與專業核對。

- `GET /api/medications/vision/status`：就緒狀態、可用品項與圖片數、來源版本。不是模型準確率或推論健康檢查。
- `POST /api/medications/vision/search`：`{"images":["data:image/jpeg;base64,..."],"imprint":"可選的完整刻字"}`。僅接受 1–2 張 JPEG／PNG／WebP，單張 8 MB、總計 12 MB、最多 2,400 萬像素。120 秒逾時；同時一筆推論，多餘請求回 429。取消後不傳回結果，已開始的原生推論可能仍需短暫收尾。
  候選的 `matchedBy` 區分 `image`、`imprint`、`image_and_imprint`；`similarity: null` 表示沒有可用圖片特徵，不能顯示為 0 或已比對。`imprintSearch` 保留輸入、完整符合筆數與本頁筆數。兩張照片中有任一張未達門檻，即使平均分數較高，也只可標為刻字候選。未填刻字與藥盒模式維持原本圖片檢索。
- `GET /api/medications/vision/images/:sha.webp`：僅供應索引內的參考圖；不接受任意檔案路徑或任意網址。

一般圖片比對的原始照片送往目前應用程式的後端，僅保留於當次記憶體，不存入索引或對話；只有上述明確收錄操作會保存照片。本機部署時在使用者電腦執行，遠端部署時會傳至該伺服器。OCR 仍在瀏覽器處理，Gemini 仍須明確選用。任何 CV 或 OCR 失敗都不自動切換雲端。

圖片比對候選使用已下載參考圖，可離線放大對照；一般名稱搜尋、仿單或後續報告中的外部圖片連結仍可能需要網路。桌面包帶入公開藥錠參考圖與模型，驗證方式見[桌面版](桌面版.md)；手機離線 App 尚未完成。

## 驗證與限制

2026-09-28：`vision:index` 同時檢查本機 `originals/`，依目前許可證、官方原圖網址及檔案雜湊補入鏡像缺少的藥錠來源圖。使用同一 DINOv2 模型、前處理與門檻；索引照片轉為最長邊 1600 的 WebP，完整原圖仍供放大。已有鏡像鍵不被清晰圖替換，補圖來源的原始／保存／索引雜湊及取得日期記錄在 metadata；重跑可沿用特徵。已保存但無法讀取的補圖使整批失敗，既有索引保持。

本機補入鼻寧通膠囊、降脂汀錠 20 毫克及鎮頑癲膠囊 300／400 毫克四筆，正式可用參考為 6,146 張／5,791 品項；四張來源圖由查不到對應候選變為第一名，固定旋轉／壓縮版本也都在前八。這是同來源回查，不是獨立實拍準確率；原有 6,468 筆索引的圖片、向量與來源逐筆保持。2026-09-28 公開資料包已包含這四張及新索引；使用舊資料包者可依 README 補圖及建索引，勿直接覆蓋既有資料。

`npm test` 涵蓋正反面合併、外觀重複候選、刻字精確核對、來源連結過期、未就緒、併發、檔案限制與不使用雲端備援。

`npm run vision:check` 以實際模型執行參考圖旋轉／壓縮測試，在程序內阻擋 `fetch`，確認推論不下載遠端模型，並驗證空白圖拒絕。結果寫入 `test-results/vision-smoke.json`；這是整合檢查，不是獨立測試集的辨識率。可加一個本機圖片路徑，觀察該圖的候選，不會匯入資料庫。

2026-09-22 修正此檢查的取樣母體：依正式藥錠服務排除注射劑等不適用品項，並核對來源連結及圖檔；不從仍保存在硬碟的全部索引隨機要求藥錠比對。乾淨安裝實測可用 6,142 筆／5,787 品項，八张等距取樣的變形圖有 6 張在前八名，兩張仍漏查，外部 fetch 次數為 0。這與舊母體的結果不能直接當作品質提升比較，正式模型與門檻未改。

2026-09-19 的 8 張等距取樣參考圖經 12 度旋轉、JPEG 壓縮後，5 張原品項出現在前 8 個候選，另 3 張未找到原品項。官方圖中的尺規、背景及外觀相近品項會干擾排序，因此介面明示為試用功能。空白圖被拒絕，使用者提供的藥盒圖沒有被強制配成藥錠。推論測試未使用網路；預熱後此電腦測得約 0.1–0.2 秒，不能推廣成其他硬體的速度保證。

仍需另行收集具正確標籤、不同手機與光線的臺灣實拍藥錠照片，評估 Top-K 候選召回、未知藥拒絕、相似外觀混淆及刻字品質，再決定是否微調模型或增加專用分割模型。現在的模型無法保證判斷「這不是藥」、辨別未收錄品項或找出混拍的兩種藥；純色藥錠與小刻字尤其需要人工核對。藥袋文字使用 OCR；藥盒圖庫見下節。

## 藥盒圖庫

同一個 DINOv2 模型另搜尋 `data/vision/packages/index.db` 與 `images/`。索引 metadata.kind 必須是 `package`；藥盒與藥錠互不混搜，並共享後端推論排隊狀態。包裝每一輸入視角的最低相似度暫定 0.75，未經獨立資料校準，不是正確率。保留最多 8 筆許可證候選。

- `GET /api/medications/packages/status`：可用包裝品名數、唯一照片數、許可證連結數。
- `POST /api/medications/packages/search`：照片格式與限制同藥錠端點；只做影像檢索，不跑 OCR。
- `GET /api/medications/packages/images/:sha.webp`：供應索引內包裝參考圖，來源不冒稱 TFDA 官方圖片。
- `POST /api/medications/packages/references`：`images`、`productName`、`sourceNote` 與 `confirmed: true`。只接受使用者核對後明確收錄，1–2 張同一品項照片；不接受任意外部圖片網址。完整品名須在 TFDA 主檔存在，保留所有完全同名許可證，以後端主檔為準。編碼為 WebP、計算特徵成功後才交易式更新 SQLite。取消或失敗的未索引圖檔不會被搜尋或供應。相同圖／許可證鍵不累加。

包裝圖片是按使用者核對的品名連結候選，並未藉照片確認許可證、成分或劑量。主檔品名改變或許可證資料消失時，搜尋不返回過期候選。資料與照片只保存在本機資料目錄，不提交 Git；部署遠端服務時需另外安排持久儲存與照片來源授權。此功能不自動爬取藥局圖片。

初始參考：使用者提供的 408 × 169「普拿疼伏冒加強錠」圖片（僅供此專案本機使用），1 張照片連結 2 筆同名許可證。2026-09-19 禁止 fetch 的實際模型檢查：原圖相似度約 0.974，8 度旋轉／JPEG 壓縮後約 0.880，皆返回兩個候選；另一張藥錠測試圖未過門檻。這是相同參考圖的變形測試，不代表能辨認未收錄藥盒或真實世界準確率。仍須擴充不同藥品、規格、包裝版本與獨立手機實拍驗證。
