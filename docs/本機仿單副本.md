## 下載與離線重建

```powershell
# 一次取得目前五份已核對版本；只接受目錄中的來源，不接受任意網址
npm run data:cache-documents -- --all

# 個別來源
npm run data:cache-documents -- --id=kbt-2023

# 從本次封存檔離線重建，保持原始取得時間
npm run data:cache-documents -- --file=data/raw/source-documents/documents-1790177230499.json
npm run data:cache-documents -- --file=data/raw/source-documents/documents-20260924-somin-fencaine.json
```

可透過 `DRUG_DB_PATH` 指定隔離資料庫。每份下載上限 5 MB／30 秒，TLS 正常驗證、不跟隨重新導向。匯入前必須符合已核對的 SHA-256、PDF 標記、許可證與完整成分集合；來源改版或檔案損毀即停止，不把 HTML 錯誤頁當 PDF。多筆全部驗證後交易匯入；不改寫藥品、交互作用、仿單規則或對話。

SQLite `local_source_documents` 保存原始 PDF BLOB、來源 ID／網址、取得日期和 SHA-256；封存檔在 `data/raw/source-documents/` 保存同樣資訊及原始檔 base64。同一有效副本重新匯入時不刷新取得日期。損毀副本可用已核對封存檔修復，沒有副本時仍顯示原始來源連結。文件保留原權利狀態，公開下載不等於取得額外商用或再散布授權。

新增版本時須先核對完整文件及產品，以新來源 ID／雜湊加入 `server/medications/source-documents.ts`，保留舊條目供已儲存報告重開。不能只改雜湊來繞過檔案變動檢查。新查詢也會重新核對產品成分，避免資料主檔變動後套用舊產品來源；歷史報告仍保留原本版本與日期。

## API 與介面

- `GET /api/medications/source-documents/:sha256.pdf`：只提供已保存且通過已核對雜湊的 PDF；不存在、損毀或未登錄來源回傳 404，不轉接外部網站。
- `GET /api/medications/source-documents/:sha256.json`：提供同一副本的標題、原始來源、取得日期、長度及本機 URL，供儲存報告開啟閱讀器；不回傳 PDF BLOB。
- `localLabel.document`、`safety.alerts[].sources[].document`：可用副本的 metadata。連結精確對應來源 URL，不能把同成分、不同版本或不同產品的文件附到另一筆提醒。
- 儲存 Markdown 保留本機 URL、來源 URL、取得時間及雜湊。重開仍需連至保存此副本的專案服務；把純文字報告移到另一台沒有資料庫的主機，不會憑空帶走 PDF。
- 閱讀器採 PDF.js 畫面渲染，不重排原文表格、不執行來源 JavaScript。翻頁與關閉會取消舊工作，避免舊頁晚到覆蓋；檔案失效顯示明確訊息，其他藥品功能可繼續操作。

## 桌面套件修正

`scripts/package-desktop.mjs` 原先未列入後端已使用的 `parse5`。本次補上固定安裝版本 8.0.1 及相依 entities 的桌面鎖檔。建置外部依賴清單與桌面 manifest／lock 相符；Vite 僅在開發分支動態載入，桌面啟動明確使用 production。這是相依套件修正，不表示已重新驗證原生 Electron 視窗或繞過 Windows AppControl。

完整回歸另遇到首次啟動已驗證資料夾改名的 Windows `EPERM`。`electron/initial-store.cjs` 對相同父目錄下的 `.seed-UUID` → `store` 加入有上限重試，只處理 `EPERM`／`EACCES`／`EBUSY`；其他錯誤立即拋出，持續失敗也會回報。沒有刪除既有資料、放寬權限或停用安全機制。既有安裝檔尚未重新封裝。
