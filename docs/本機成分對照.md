# 本機成分對照

一般「用本機資料分析」和比賽案例不需要金鑰、Gemini 或 Ollama。RxNorm 對照資料由管理者先連線查核，或在使用者按「補查線上仿單與標準名稱」時取得；之後可離線重用。

## 查核原則

1. 使用 [RxNorm 精確名稱查詢](https://lhncbc.nlm.nih.gov/RxNav/APIs/api-RxNorm.findRxcuiByString.html) 的 `search=0`，只忽略大小寫。不得改成會忽略鹽類的 normalized 或 approximate 查詢來自動定案。
2. 精確結果須只有一筆，且 [概念屬性](https://lhncbc.nlm.nih.gov/RxNav/APIs/api-RxNorm.getRxConceptProperties.html) 為有效單一成分 IN 或 PIN；不接受商品名、複方或劑型產品。
3. [成分關係](https://lhncbc.nlm.nih.gov/RxNav/APIs/api-RxNorm.getRelatedByType.html) 必須只有一個 IN，並與原有精確 DDInter 結果相容。
4. 僅保存成分名稱關係；不代表不同鹽類、劑型、途徑、含量或臨床作用完全相等，亦不換算劑量。

TFDA 明示的 `EQ TO` 別名支援括號內空格及連續多個等名標記；原文、鹽類與其他限定詞仍保留。不是 `EQ TO` 的括號不會被任意刪除。解析方式更新時，先前已核對成功且仍屬明示別名的紀錄可沿用原日期；先前的「查無」不代表新增別名已查過。

如果標準成分名與 DDInter 名稱不同，程式會尋找 DDInter 完整名稱自身的精確 RxNorm 紀錄。兩邊須對應同一個 IN；DDInter 端必須直接匹配 IN，不能用 PIN、商品、複方、相似名稱或產品限定別名代替。若符合多個 DDInter ID，保留未知。每次查詢依當前 DDInter 目錄重查 ID，匯入更新不會繼續使用已移除的名稱。

例如 `aspirin` 與 DDInter 的 `Acetylsalicylic acid` 都已有 RxCUI `1191` 的精確紀錄，可用同一成分概念連接既有交互作用配對。這個步驟不新增或更改 DDInter 的風險等級。藥品明細及儲存報告會列出 DDInter 原名、ID、RxCUI、查核時間、版本與兩端來源。

紀錄保存在 `data/drugs.db` 的 `ingredient_registry` 表。保留核對時間、[RxNorm 資料版本](https://lhncbc.nlm.nih.gov/RxNav/APIs/api-RxNorm.getRxNormVersion.html)、精確查詢 URL、匹配概念與 IN 成分。產品仿單提供的別名依據不能跨產品誤用。

原始 HTTP 回應快取 24 小時；成分紀錄持續保存，供斷線使用。線上重查失敗不改日期，成功得到查無或歧義則不再使用舊對照。超過 30 天顯示更新提醒，此門檻不是醫療有效期限。重用紀錄不等於已核對目前最新版本。

## 管理操作

在專案根目錄執行：

```powershell
# 只核對比賽案例
npm run data:enrich -- --case

# 按未註銷品項中名稱出現次數，分批核對 100 筆
npm run data:enrich -- --limit=100

# 只查尚無紀錄的新名稱，適合別名解析更新後補齊資料
npm run data:enrich -- --missing --limit=100

# 核對尚未保存的 DDInter 完整名稱，可重複執行以接續
npm run data:enrich-ddinter -- --limit=100

# 需要更新已保存的 DDInter 名稱時，加入 --refresh
npm run data:enrich-ddinter -- --refresh --limit=100

# 本機統計，不對外連線
npm run data:enrich -- --audit
npm run data:enrich-ddinter -- --audit
```

成分批次預設略過 24 小時內已查核紀錄；`--missing` 只處理缺少紀錄的名稱。DDInter 名稱批次預設只補缺，`--refresh` 才會更新超過 24 小時的紀錄。兩者再次執行均可接續；連續三筆查核失敗會停止並保留已有資料。查無精確名稱屬已完成查核，不是假裝對照成功。統計另存於 `data/reports/`，`DRUG_DB_PATH` 可指定藥品資料庫。

批次只送出公開成分名稱及 ID，未傳送病人資料。依 [NLM 使用條款](https://lhncbc.nlm.nih.gov/RxNav/TermsofService.html)，批次將單程序請求限制於每秒最多 5 次；多個程序仍共用同一 IP 的限額，請勿同時啟動多個批次。

本產品使用美國國家醫學圖書館 NLM（隸屬 NIH、美國衛生及公共服務部 HHS）公開資料；NLM 不對本產品負責，也不背書或推薦本產品。

## 補入公開 CSV 沒有的官方網站配對

DDInter 官方下載 CSV 並未涵蓋整個網站。2026-09-23 在[官方 Dexchlorpheniramine 頁面](https://ddinter2.scbdd.com/server/drug-detail/DDInter1996/)確認網站收錄此成分，但現有八類 CSV 沒有它。專案可由管理者下載官方成分图的配對快照，一般使用者查詢仍完全離線，不自動擷取網站或呼叫 Gemini。

```powershell
# 先在官方網站核對成分與 ID；一次最多指定五個 ID
npm run data:enrich-ddinter-web -- --id=DDInter1996

# 重新安裝時，可從已保存的封存檔離線匯入；以下是本次實際檔名
npm run data:enrich-ddinter-web -- --file=data/raw/ddinter-web/DDInter1996-1790174250943.json
```

本次官方[成分圖資料](https://ddinter2.scbdd.com/server/grapher-datasource/DDInter1996/)含 253 個不同配對；網頁列表顯示 254 列，不能將這個圖資料快照稱為整個網站列表的完整匯入。新增後本機總配對 160,235 → 160,488。Somin 與 Cypromin 對應的 Dexchlorpheniramine／Cyproheptadine 列為 Moderate，與年齡提醒分開；沒有推算一個月嬰兒的風險機率或處置。

原始回應、SHA-256、成分 ID、官方頁與圖資料網址、取得時間保存在 `data/raw/ddinter-web/` 以及 SQLite 的 `ddinter_web_snapshots`。另外兩個 `ddinter_web_drugs`／`ddinter_web_pairs` 表只存該快照的名稱與配對，CSV 原表保持不變。查詢時合併去重，CSV 既有配對優先顯示原來源；網站新增配對顯示個別成分頁及取得時間。報告儲存後保留該次來源資訊。

更新某個成分會在交易內替換它的舊快照與配對，不刪除其他快照或 CSV；成功取得空清單代表本次來源無配對，不會當作安全。ID 不符、格式錯誤、重複或多等級配對、同 ID 名稱衝突、跨來源等級衝突皆拒絕並保留原資料。CSV 重匯也檢查衝突，不會悄悄覆寫網站資料。下載／核對失敗時可重新執行；不要手改原始 JSON 或重新計算雜湊來掩蓋損毀。

此來源是網站目前公開的圖資料介面，並非承諾穩定的官方 API；結構變動會停止更新。圖資料含名稱、等級及部分機轉分類，不包含詳細機制或處置全文。本輪亦在[官方兩成分查詢結果](https://ddinter2.scbdd.com/checker/result/DDInter1996-DDInter459/)確認 Moderate(1)，並有[詳細配對頁](https://ddinter2.scbdd.com/server/interact/270023/)連結；詳細說明由下列獨立功能保存。資料沿用 DDInter [CC BY-NC-SA 4.0 條款](https://ddinter2.scbdd.com/terms/)，名稱標準化仍遵守前述精確成分關係。

## 顯示官方機轉分類

讀取時核對原始 SHA-256、來源網址、取得日期、成分 ID／名稱及配對等級；若兩份相對成分的快照都有此配對，分類須一致。缺漏、未知格式、新分類、損毀或不一致時略過機轉說明，保留既有配對與等級。每次報告重新核對，不沿用跨報告的舊快取，不改資料庫結構或原資料。CSV 配對來源仍優先；補充機轉另列自己的快照來源。
