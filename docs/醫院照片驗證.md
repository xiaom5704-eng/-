## 刻字查詢與實際網頁操作

另用人工輸入的刻字走既有 `/api/medications/match`。這是已知來源後的功能查核，**不是盲測，也不是 OCR 或 CV 的正確率**。未輸入藥名、許可證、顏色或形狀，正反面分開傳送，逐頁核對完整候選。

實際瀏覽器另驗證 Acetal：

1. 上傳同一張新的醫院原圖，同時執行正式 CV 與本機 OCR，未用 Gemini 或 Ollama。
2. 原尺寸 OCR 讀到 `PURZER`，也將背面誤讀為 `07107`，並讀到尺規數字；沒有自動把這些字當成正確藥品。
3. 點 `PURZER` 查到六個候選，其中包含愛舒疼；點圖可開啟本機 640×533 參考圖核對。
4. 人工對照照片後，在正面填 `PURZER`、背面填 `07 07`，查到完整字號 032320 的一個候選。原 OCR 文字保持，確認清單仍為 0／6，沒有自動確認品項或分析。

測試使用隔離的公開資料副本，後端禁止連外。一般名稱／刻字查詢可用，不表示照片已被自動辨認；R、SYN、CCP 的多筆結果尤其需要藥袋、原包裝及專業核對。

## 驗收結論

保留純圖片功能的試用標示及人工確認流程，不降低門檻、不將輸入照片匯入圖庫後宣稱辨識成功。完整刻字與另一面能協助查找，但不是通用的照片辨識替代品。

本輪確認了正式模型對新的外部照片仍有明顯漏查；目前不能承諾任意藥丸拍照即可辨識。後續影像改善需以有明確身分及可用授權的不同拍攝照片為依據，分開開發與驗證資料，再量測候選召回與未知品項處理。整體驗收仍為 **63%（5／8）**。
